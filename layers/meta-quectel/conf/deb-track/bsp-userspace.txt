# BSP 用户态组件：按 recipe 逐个加，不要整批扫。
#
# 每加一个，先在设备上确认它的文件真的无主：
#     dpkg -S <path>        # 必须报 "no path found"
# 然后再看它的 Depends 会不会把 Yocto 的基础库拖进来（见 DEB_TRACK_CLOSURE_DENY）。
#
# 本文件目前只有 msm-va-driver。它的场景最能说明为什么需要 deb-track：
#   msm-va-driver 在 do_rootfs 阶段装进 Yocto rootfs，
#   deploy_debian_gnome_rootfs 随后把 Debian tarball rsync 上去
#   （不带 --delete，Debian 也没有同名文件），于是 .so 留在盘上、
#   但 /var/lib/dpkg 被覆盖 → 文件无主、apt 无法升级。

# --- VA-API 硬件解码驱动 ------------------------------------------------------
# 提供两个路径，对应两套 rootfs 布局（同一个 build 产物）：
#   /usr/lib/dri/msm_drv_video.so                  Yocto rootfs
#   /usr/lib/aarch64-linux-gnu/dri/msm_drv_driver  Debian/Ubuntu rootfs
# 两者实测在 Debian 13 上均无主；Debian 的 mesa 只提供 msm_dri.so（OpenGL），
# 不冲突。
#
# 注意：它的 Depends 里有 libva，但 Yocto 的 libva 已被
# DEB_TRACK_CLOSURE_DENY 挡住 —— 那是 2023 年的 2.20.0，装到 /usr/lib/
# 会和 Debian 的 libva2 2.22（/usr/lib/aarch64-linux-gnu/）并存，
# 有被 dlopen 到旧版的风险。实测 msm_drv_video.so 的 NEEDED 只有
# libc.so.6 和 loader，它靠 libva 运行时 dlopen 加载，所以用 Debian 的
# libva2 就够，不需要登记 Yocto 的 libva。

# --- BSP 用户态：GStreamer / PAL / AI / 视觉 / Sensors / 工具 -------------------
#
# 下面 187 个包按功能分组，判定方法（2026-11，设备 Debian 13 trixie）：
#   1. 取目标 rootfs 的 dpkg 数据库：117204 条已登记路径
#   2. 逐个 deb 展开文件列表，与上述路径做精确交集        → 0 冲突
#   3. 再做 basename 比对，仅限共享库目录（/usr/lib、
#      /usr/lib/aarch64-linux-gnu）下的同名 .so          → 0 冲突
#   4. 模糊归一（剥 .so.* / ABI 数字 / t64 / lib 前缀）核对
#      Debian trixie 的 71107 个包名                     → 无同功能包
#
# 私有子目录里的 vendored 副本不算冲突：onnxruntime 的
# /usr/lib/qwen35/lib/libonnxruntime.so.1.27.0 和 npu-llm 的
# /usr/lib/npu-llm/voice/sherpa_onnx/lib/libonnxruntime.so 都靠 rpath
# 加载，与 Debian 的 /usr/lib/aarch64-linux-gnu/libonnxruntime.so.1.21
# 互不影响。
#
# 特意排除的空包（0 文件，dpkg 无可登记内容）：
#   qcom-audio-plugin-headers qcom-pal-headers qcom-vui-interface-header
#   qcom-fastcv-binaries quec-pcie-mhi quec-sprd-pcie quec-ufs-size
#   r8168 yt6801
#
# qcom-pw-pal-plugin 的文件已在盘上工作（PAL 的 sink/source 全靠它的
# pw-pal-plugin.conf 和 libpipewire-module-pal.so），本次先登记，但它装的
# /usr/lib/systemd/system/pipewire-pulse.socket 与 Debian 已安装的
# pipewire-pulse 的 user 作用域单元监听同一地址（%t/pulse/native），
# 属运行期资源争用，不是文件冲突，需单独处理，暂不动。
#
# pillow 和 python3-opencv：Debian trixie 源里有 python3-pil /
# python3-opencv，但目标镜像没装，且两者文件与 Debian 已登记路径交集为 0
# （pillow 在 dist-packages/PIL，opencv 在 python3.12/site-packages/cv2，
# Debian 用 dist-packages），卸载只删自己的文件。若日后有人在设备上
# apt install python3-opencv，需靠 Replaces/Provides 协调。

# Names are deb Package names (not recipe names); see conf/deb-track/README.md.

# Debian 13 (trixie) does not ship.  Verified by comparing all ~117k paths

# no path, no basename in a shared library directory, and no apt package

#     unmanaged: Debian's pipewire-pulse owns the user-scope unit at the same
#     listen address and the class must not fight it.
