# Package names that the Debian/Ubuntu base either ships or declares a
# Conflicts/Replaces/Breaks against.
#
# One package name per line; '#' starts a comment.  No globs: this is a snapshot
# of real names, so an entry either matches a package or it does not.
#
# Why this list exists
# --------------------
# The BSP set (kernel.txt / firmware.txt / bsp-userspace.txt) is QTI/Quectel
# private and does not overlap the distro.  But their *dependency closure* does:
# resolving `Depends` from deploy/deb reaches Yocto's own copies of packages the
# distro also ships.  Installing those puts a second copy of a library the
# distro already owns next to it, and dpkg then either refuses to unpack over a
# file the distro owns or refuses the package outright because the distro
# package declares a conflict against it.
#
# The rule: when the closure reaches a package that is not named explicitly in
# one of the three list files, and this list contains its name or the distro
# owns one of its file paths (see distro-owned-paths.txt.gz), skip it and keep
# the distro's copy.  The dependency stays unsatisfied, which dpkg tolerates
# under --force-depends because the distro library is already on the rootfs.
#
# Why the Conflicts/Replaces names are included
# ---------------------------------------------
# Some collisions never touch the same path and do not share a name, because the
# distro renamed the package and kept a Conflicts against the old name:
#
#   Yocto libjpeg62   -> Debian libjpeg62-turbo declares Conflicts: libjpeg62
#   Yocto libharfbuzz0-> Debian libharfbuzz0b   declares Conflicts: libharfbuzz0
#
# dpkg refuses those with "conflicting packages - not installing", which
# --force-overwrite cannot help with.  Collecting the declared names catches
# them without guessing at fuzzy name similarity.
#
# Where the names come from
# -------------------------
# Extracted read-only from the prebuilt distro tarballs:
#   prebuild/debian-gnome-rootfs.tar.xz   Debian 13 (trixie)   1502 packages
#   prebuild/ubuntu26-gnome-rootfs.tar.xz  Ubuntu 26            1635 packages
# plus every name those packages declare in Conflicts/Replaces/Breaks/Provides.
# Union after removing the BSP list names themselves: 5727 names.
#
# To refresh after a distro bump, read var/lib/dpkg/status out of each tarball
# and collect `Package:` plus the Conflicts/Replaces/Breaks/Provides operands.
# A stale entry is harmless; a missing one means the closure may pull in a
# duplicate or a conflicting package.
#
# NOTE: build-time input only.  Reading prebuild/ is done offline to produce
# this file; nothing here touches prebuild/ during a build.

# --- Packages that only exist to feed opkg's update-alternatives ------------
# BitBake splits util-linux and procps into one package per command and
# installs each as /usr/bin/<cmd>.util-linux (or .procps), then registers an
# alternative so that /usr/bin/<cmd> is a symlink into opkg's database under
# /usr/lib/opkg/alternatives.
#
# On a Debian/Ubuntu rootfs this is both useless and harmful:
#   - Debian ships util-linux and procps as whole packages, so every one of
#     these commands already exists at the real path;
#   - the postinst calls update-alternatives-opkg, which is in
#     DEB_TRACK_CLOSURE_DENY, so it is absent;
#   - it then runs `mkdir /usr/lib/opkg`, which under
#     --force-script-chrootless resolves outside the rootfs and fails with
#     "Permission denied", leaving the package half-configured (iF).
#
# Observed exactly that on 2026-11 with util-linux-flock and
# util-linux-taskset.  Listing all of them keeps the closure from pulling
# any of them in later.
